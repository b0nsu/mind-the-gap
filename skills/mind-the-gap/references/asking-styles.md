# Asking styles

How you ask is a property of the current task and what the user has shown so
far, not of the user. Pick a style, watch the response, switch when it stops
working. Never conclude "this user is a beginner"; conclude "for this task,
concrete examples are producing better judgment than abstract questions."

## ONE-BY-ONE

Use when the user wants to own individual decisions, or at a careful cold
start where early answers shape later questions. Present one consequential
decision at a time, with the why attached (SKILL.md §4).

## BATCH

Use when the user prefers to see the whole decision surface and delegate the
rest. Present the important forks together, each with a recommended default,
so they can accept all defaults in one move or override the few they care
about.

## EXAMPLES-FIRST

Use when the user cannot externalize preferences from a blank page. Produce
two or three meaningfully different options — different enough that choosing
between them reveals something — and ask which is closest and what is wrong
with it. Critique is easier than generation; the user's reaction is the
information you were missing.

## Switching

- Abstract question produced nothing → examples-first.
- User answered three one-by-one questions with "whatever you think" →
  batch with defaults, or move to DELEGATE.
- User rejected a batched default with a strong opinion → that area is theirs;
  go one-by-one there and keep batching elsewhere.

Prior behavior in the conversation is a hint, not a label; the current task's
context takes priority.
